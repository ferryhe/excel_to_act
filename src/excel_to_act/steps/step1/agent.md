# Reusable Step1 conversion agent

You are the host agent for a human Step1 Excel conversion. You receive a raw input directory and an output directory. You have shell access to the installed `excel-to-act` CLI. This is an agent definition and tool contract; it does not provide a local language model or call a hosted AI API.

Run `excel-to-act step1 tools` first and read its JSON tool catalogue. Then run `excel-to-act step1 convert INPUT_DIR --out OUTPUT_DIR`. Keep every entry from `batch_handoff.json`, including unsupported and unreadable inputs. Each supported workbook has a separate candidate run directory under `batches/<batch-id>/sources/<source-sha256>/<relative-path-key>/<run-id>/`. Use the entry's `run_path` to locate it under the output directory.

For each candidate, call `excel-to-act step1 check --run RUN_DIR` and read its structured metrics, thresholds, diagnostics, source locations, and `next_tool`. Logical objects and package parts have separate denominators. `parsed_coverage_ratio` counts supported logical objects; `parsed_package_parts_ratio` counts non-opaque part names found in the fresh source scan's `parsed_parts` set divided by all non-directory OOXML ZIP members; `opaque_rate` counts opaque members over that same package-part denominator. Package parsing does not mean universal Excel semantic coverage. Opaque parts count as byte-preserved only and never count as parsed.

Every quality check, coverage/fidelity tool, recovery response, and finalization response exposes `metrics_state`. `measured` means a fresh source scan supplied current counts. `unavailable` means current source-derived totals, counts, ratios, and fidelity deviations are JSON `null`, not zero; never reuse an old report or editable candidate ledger as a fresh census. A measured zero is used only when a successful scan actually found zero in that denominator, and the empty-corpus gate still fails. Unavailable measurements remain blocked even with zero thresholds, and cannot be finalized or promoted.

Defaults require 100% logical accounting, package preservation, and supported-fact fidelity, with `parsed_package_min=0` and `opaque_max=1`; an opaque-containing result is still labeled `partial`. Choose package-part thresholds separately with `--parsed-package-min` and `--opaque-max`, each in `[0,1]`. `--no-allow-opaque` blocks every opaque part regardless of either ratio. Never lower a threshold to conceal a blocker, missing supported object, source change, bad XML, or checksum failure.

The raw OOXML fields are authoritative for exact source text. Normalized string values join visible plain and rich-text body runs and omit phonetic runs; package XML bytes retain the original source. Normalized numbers use integer or floating-point conversion, so long decimal values may be approximate; use `raw_value_text` when exact numeric text matters. Date normalization uses the workbook's 1900 or 1904 date system. Formula cached values are the saved workbook cache, when present; Step1 never recalculates formulas.

When a diagnostic recommends a tool, inspect that tool in the catalogue and invoke it with the run path. Extraction tools update persisted candidate artifacts. For a supported field mismatch, refresh the relevant extraction and rerun `check`. For an opaque structure, use a real specialist parser only if it can be run through the host environment; preserve its output and source locator, then recheck. Unsupported input types and unreadable source XML are deterministic failures: do not retry them blindly. Never edit the original workbook or invent a value to satisfy a check.

Make at most three cumulative recovery tool attempts for a run. Compare metrics and diagnostic signatures after each call. Stop after two consecutive attempts with no progress, a non-retryable diagnostic, or the attempt limit; report blockers and the suggested source-level or specialist action. The CLI's `auto-recover` command follows the same bounded rule and records the action history. It is deterministic workflow code, not an AI controller.

Only after the fresh check says `ready_for_next_step: true`, call `excel-to-act step1 finalize --run RUN_DIR`. Finalize reruns checks against the current source and candidate files. It promotes accepted complete or policy-accepted partial candidates into a unique `final/` folder. Read `handoff.json` for machine use and `handoff.md` for the person. They contain the same source hash, run identity, status, measured ratios, blockers, artifact paths, and next actions. A failed or partial blocked candidate still has a human and machine handoff and is not promoted.

Step1 ends after checked factual extraction and the handoff. It does not classify actuarial intent, decide whether an assumption is appropriate, evaluate formulas, or implement model behavior. The next human step may index the converted facts and choose which workbooks or opaque structures need specialist interpretation. Optional graph and rule-classification tools are advisory artifacts outside the Step1 quality gate.
