# Step 4 Agent Contract: Generate the Approved Python Model

A new native v2 workflow has writable Stage 1–5 checkpoints and requires current Agent and actual-human review. Legacy v1 checkpoints and attached-v2 inherited Stage 1–5 evidence are read-only. Legacy TypeSafe delegation does not authorize current v2 reviews.

Step 4 emits code for the source-bound design accepted at Stage 3 and runs a bounded standalone smoke check. It does not compare results with Excel. It requires both current Stage 3 confirmations under the active workflow's review policy.

Write new instructions, report narration, and generated artifact prose in English. Preserve source values, formulas, identifiers, and immutable provenance verbatim. Only the repository-root `README.md` and `README.zh-CN.md` are approved bilingual documentation exceptions.

This contract is workbook-independent. Obtain all targets, inputs, dimensions, selectors, external boundaries, and equations from the accepted design and confirmed catalog. Do not reuse another workbook's source coordinates, parameter values, vector counts, or approvals. Inspect the tool and adapter capabilities for this design; missing support is a blocker, not permission to assume another model's layout.

Read `step4 tools` and the accepted Stage 3 design report. Step 4 creates modular bundles only. Run `step4 capture-external --workflow DIR` to capture the catalog-bound formula-derived inputs required by the current modular contract, then run `step4 discover --workflow DIR` to build a fresh active trace. Discovery uses source formula text and literals; it does not call Excel or read formula caches. Run `step4 plan --workflow DIR --implementation INPUT.json` with the implementation map supplied for the accepted design. The preflight rechecks the source, current Stage 3/capture/trace bindings, exact equation-family coverage, named references, metadata slots, and execution schedule. It compiles the projected functions and driver in memory and writes `implementation_plan.json/.md`; it does not run the model or advance Stage 4. Only after this preflight passes, run `step4 generate --workflow DIR`. Generation consumes the current preflight and its bound discovery. Normally omit `--trace` to use that trace. If explicitly supplied, `--trace TRACE.json` must be the exact latest passing Stage 4 discovery trace bound by the current implementation preflight; Stage 3 traces and older discovery revisions are rejected. The command rechecks the source workbook, trace, formulas, and stage bindings before writing a new Stage 4 revision. An accepted design without its current semantic plan/check or implementation preflight is blocked; return to Step 3 to finish the modular design, then run `step4 plan`. It compiles the generated files and runs a bounded standalone smoke in a temporary folder without the workbook or project package; this is code-generation evidence, not a native comparison.

Review `generation_report.json/.md` and every file named in `model_manifest.json`, including `model.py`, `pricing.py`, `formula_families.py`, `modular_runtime.py`, the separate input ledgers, and the source map where required. Confirm that formulas are emitted as executable Python, the bundle imports only the Python standard library and its bundled runtime, and raw input values were reread from the unchanged workbook. Formula cells must not appear among raw inputs; saved formula-cache values must never be emitted as constants. Unsupported active formulas, cycles, external references, and unbound inputs must remain blockers.

## Modular-model acceptance

Review the logical variables and equation families as well as execution. Scalars must remain distinct from time-projection series and age/category tables. A projection variable's initialization, recurrence segments, time lags, and source exceptions belong to one named variable. Emit compact functions, category operations, ordered recurrence loops, and root reductions. Function definitions must follow unique equation families rather than the number of spreadsheet cells.

Keep Excel coordinates in a separate source map and reconciliation adapter. Model equations should use logical variable names and indices. Formula-derived values remain calculations; neither a source cache nor an earlier model result becomes raw input. An unmatched required family blocks modular generation.

The modular emitter keeps business input variables, accepted external vectors, and adapter metadata in separate ledgers. Source coordinates remain in the adapter and source map; model functions use logical variables and indices. A derived variable may start from an accepted axis-metadata coordinate only when the semantic plan declares `source_role: accepted_axis_metadata`; that seed is hash-bound in the metadata ledger, initialized into its declared logical index, and excluded from raw business inputs. Ordinary source-backed initial conditions remain in the raw ledger. Formula-derived external vectors are an explicit reviewed exception: Stage 4 captures only the catalog-declared vector IDs, shapes, and shared key axis with a fresh macro-disabled native Excel rebuild, binds the source formulas and axes, and stores those values in a separate external ledger. Their upstream producer formulas stay outside the generated model. Formula caches and earlier model results are never inputs. Stage 5 captures a fresh native result and compares the external values, axis keys, source formula cuts, and active model formulas independently. Counts, lengths, keys, and source ranges come from the confirmed catalog. The current capture path requires a nonempty set of finite one-dimensional vectors sharing one declared key axis; unsupported boundary shapes or missing capture support require a revised implementation plan.

The no-argument entry retains the saved Step 3 guards, including every declared raw input coordinate. A separate `model.py --inputs REQUEST.json` route is emitted only with a complete current Step 3 interface and an approved fixed-trace support domain; it validates logical input values, axes, ranges, source bindings, same-request external values, and bundle files before calculation. The request has `inputs` and `external_data` objects. A different source or unsupported trace/producer change needs its own reviewed design and bindings. Check workbook-specific assumptions before promising reuse. A generated bundle is not a general workbook converter.

Do not alter the source workbook or earlier stage artifacts. The smoke does not prove Excel equivalence; Stage 5 separately validates the generated code and a fresh native Excel result. Review the exact Stage 4 report pair and bundle, then record Agent approval with `workflow confirm --workflow DIR --stage 4 --reviewer agent --decision approve --message TEXT`. Record actual-human approval only after an explicit response. The current v2 CLI disables legacy TypeSafe delegation and live TypeSafe review. Stage 5 cannot start until both required decisions are current.

A rejection from any reviewer makes that revision ineligible for later approvals; create a replacement artifact and obtain fresh Agent and actual-human decisions.

## Shared workflow and decision order

Treat `input/` as the source Excel area and `output/` as the home for each new source-bound workflow and its reports. Start a new conversion from the current workbook and user request; never carry case facts or approvals from another workbook or run.

Read `stepN tools` and choose the existing actions that answer this case's open questions. Explore from the source and current bound evidence, inspect each action's checks and outputs, then prepare the paired machine-readable JSON and reader-facing Markdown handoff. Review all files named in the handoff and confirm their source and upstream bindings before asking for a decision. Do not continue when a required check fails or an input is stale.

Before entering a stage, run `workflow status` and verify that the stage is currently permitted and every required upstream decision and artifact is current. A successful tool check, report creation, draft CLI action, or clarification does not itself approve a stage or advance the workflow. Keep legacy standalone source-exploration APIs available for discovery; they do not create a workflow approval.

The current review order is Agent first, then the actual human on the exact current JSON/Markdown pair. `workflow confirm` records approvals; use `workflow reject` with an explicit `--return-to` route for rejection. Record the human decision only after an explicit response. Legacy TypeSafe delegation and live review commands are disabled in v2. The Step 3 input-boundary checkpoint always requires an actual human decision.

Ask the user when target, scope, input kind, axis, units, or business interpretation is materially unresolved. Keep unknown facts marked as unknown; do not turn planning into measured execution or claim checks that did not run.

When a reviewer rejects a report at Stage 4, route it to the responsible current or earlier stage with `workflow reject --workflow DIR --stage 4 --reviewer agent|human --return-to 1|2|3|4 --message TEXT`. Keep rejected history, revise affected reports, rerun checks, and obtain fresh Agent and actual-human reviews before advancing. Inspect `workflow status` after each decision.
