# Step 6 Agent Contract: Internal Tool Delivery

Step 6 packages the exact approved Step 4 standalone bundle from current, approved Stages 1–5. Those stages are local in a native v2 workflow or read-only from an attached pinned v1 parent. The candidate binds that origin, source, package files and hashes, interface and runtime dependencies, internal version and permission, exact request and native comparison, and an isolated package-entry smoke result.

Read `step6 tools` and `workflow status --workflow DIR`. Attach a current legacy parent with a separately verified comparison. For a native workflow with an approved exact-case Step 5 report, use that report as `--comparison` with a request it covers; other native comparisons must be separately bound. Review the immutable candidate JSON/Markdown pair and its package ledger. A passing smoke or an old Step 6 report never approves delivery. Record Agent review, then obtain an actual human decision on this exact pair. A new publication-scoped TypeSafe authorization would be required to substitute for that human; old delegation does not apply.

Only after the current pair is genuinely approved, `step6 deliver` copies the same files, runs the delivered entry in isolation, verifies exact readback, and records the effective internal version. Failure leaves no effective new delivery. `step6 revoke` makes the version inactive without deleting its historical package. Step 7 requires current approval and effective delivery; neither stage authorizes production or public distribution.

Reject the current Step 6 pair with `workflow reject --workflow DIR --stage 6 --reviewer agent|human --return-to 1|2|3|4|5|6 --message TEXT` on native v2, routing to the responsible stage. An attached v2 workflow has read-only inherited Stages 1–5, so its only Step 6 route is `--return-to 6`; attach a new root if its pinned parent needs correction. Legacy v1 is read-only in the current workflow.
