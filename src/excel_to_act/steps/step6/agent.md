# Step 6 Agent Contract: Internal Tool Delivery

Step 6 packages the exact approved Step 4 standalone bundle from current, approved Stages 1–5. Those stages are local in a native workflow or read-only from a pinned parent in an attached workflow. The review pair binds that origin, source, package files and hashes, interface and runtime dependencies, internal version and permission, exact request and native comparison, and an isolated package-entry smoke result.

Read `step6 tools` and `workflow status --workflow DIR`. For a native workflow with an approved exact-case Step 5 report, use that report as `--comparison` with a request it covers; other native comparisons must be separately bound. Attachment requires a production parent with manifest schema `conversion.workflow.v1`, stage keys `1`–`6`, current Stage 1–5 approvals, and a separately verified comparison. Review the immutable package JSON/Markdown pair and its package ledger. A passing smoke is technical evidence. Record Agent review, then obtain an actual human decision on this exact pair. TypeSafe delegation and live review commands are disabled.

Only after the current pair is approved, `step6 deliver` copies the same files, runs the delivered entry in isolation, verifies exact readback, and records the effective internal version. Failure leaves no effective delivery. `step6 revoke` makes the version inactive while retaining its package. Step 7 requires current approval and effective delivery; neither stage authorizes production or public distribution.

Reject the current Step 6 pair with `workflow reject --workflow DIR --stage 6 --reviewer agent|human --return-to 1|2|3|4|5|6 --message TEXT` on native workflows, routing to the responsible stage. An attached workflow has read-only inherited Stages 1–5, so its only Step 6 route is `--return-to 6`; attach a new root if its pinned parent needs correction.
