# Workbook inventory fidelity rules

## Contract

These rules define how workbook source facts are retained alongside normalized inventory fields. They apply to extraction, persisted artifacts, and readers of both current and older inventory records.

## Field rules

| Rule | Serialized fields | Allowed projection | Counterexample and runnable assertion |
| --- | --- | --- | --- |
| Cell values retain source facts beside normalized values. | `CellInventory.raw_value_text`, `ooxml_cell_type`, `value`, `number_format`, `workbook_date_system`, `date_serial_text` | `value` may parse numbers, turn date serials into ISO text, or expand a shared-string index. `number_format` and the 1900/1904 date system remain separate facts; a display string does not replace the source serial. | A high precision numeric `<v>` can normalize to a different Python number, and shared-string `<v>0</v>` denotes the first string, not numeric zero. See `test_raw_facts_normalized_fidelity_and_persisted_recovery` and `test_visible_shared_and_inline_text_ignores_phonetics_and_preserves_raw_xml`. |
| Shared and inline strings retain their distinct source representations. | `CellInventory.raw_value_text`, `CellInventory.value`, `source_facts.json.cells[].inline_string_text`, `package_parts.json[].name`, `package_parts.json[].preserved_path` | For a shared string, `raw_value_text` is the shared-string index; for an inline string it is `None`. `inline_string_text` stores expanded inline text. Normalized `value` concatenates visible plain/rich body runs, ignores phonetic runs, and preserves spaces and empty strings. Original shared-string and worksheet XML bytes are located by `name` and `preserved_path`; scalar inventory fields cannot reconstruct those bytes. | A shared-string cell can have `raw_value_text` `0` while its value is a two-character string with Unicode code points U+6F22 and U+5B57; inline text with phonetic runs still normalizes to the visible text, including preserved spacing or an empty string. See `test_visible_shared_and_inline_text_ignores_phonetics_and_preserves_raw_xml`. |
| Dates require numeric source data and a date-formatted cell. | `raw_value_text`, `ooxml_cell_type`, `date_serial_text`, `workbook_date_system`, `number_format`, `value`, `cached_text`, `cached_value` | The serial can be normalized to a date/time string using the workbook date system. The original serial text, type, system, and format stay available. | A shared-string index `0` in a date-formatted cell is not a date serial; numeric serial `45293` can project to `2024-01-02T00:00:00`. See `test_date_serial_requires_numeric_source_type_and_raw_number`. |
| Formula source and usable formula are distinct. | `raw_formula_text`, `raw_formula_attributes`, `formula_present`, `formula` | A shared-formula follower with an empty source `<f>` may receive an expanded normalized `formula`; source text and attributes remain as read. Array and data-table `t`/`ref`/`si` attributes are retained as facts. This does not capture complete array spill or dynamic-array semantics. | D3 has no source formula text and shared-formula attributes `t=shared, si=0`, while its normalized formula is `=B3*2`. The array formula at D4 retains source text `1+1` with `t=array, ref=D4`; the data-table formula can have no usable normalized formula. See `test_raw_facts_normalized_fidelity_and_persisted_recovery` and `test_visible_shared_and_inline_text_ignores_phonetics_and_preserves_raw_xml`. |
| Cached source text, node presence, and parsed availability are separate. | `cached_text`, `cached_text_present`, `cached_value`, `cached_value_available` | `cached_value` may parse source text, shared strings, booleans, or date serials. `cached_text_present` records a `<v>` node for a formula; `cached_value_available` records whether a usable stored result was read. | Stored `0`, `false`, and empty string are valid results. An absent `<v>` is unavailable. See `test_raw_facts_normalized_fidelity_and_persisted_recovery` and `test_cached_value_boundaries_preserve_availability_and_types`. |
| Error values and number formats remain data facts, not rendered output. | `ooxml_cell_type`, `raw_value_text`, `value`, `cached_text`, `cached_value`, `number_format` | Error text such as `#N/A` remains a value; number formats remain alongside the numeric value. No formatted display string is computed. | C1 has OOXML type `e`, value `#N/A`, date-like format `yyyy-mm-dd`, and no `date_serial_text`; it is not a date. A value `0.05` with format `0.00%` is still stored as `0.05`, with the percent format available separately. See `test_date_serial_requires_numeric_source_type_and_raw_number` and `test_manifest_inventory_graph_classification_confirmation`. |
| Additive fields remain optional for existing `phase1.v1` inventories. | The ten additive `CellInventory` fields, `SheetInventory.source_identity`, `RangeInventory.source_identity`, and nested `SourceLocation.source_identity` | Missing fields use model defaults; absent measurement remains unknown (`None`), while `raw_formula_attributes` defaults to `{}`. Reading an old artifact does not establish facts it never measured. | An old inventory without `formula_present`, `cached_text_present`, or `workbook_date_system` must load with those fields as `None`. See `test_old_phase1_inventory_without_additive_fields_reads_through_store`. |

`schemas/workbook_inventory.schema.json` is the current `WorkbookInventory.model_json_schema()` export; `test_exported_workbook_inventory_schema_matches_model` keeps the checked-in contract aligned with the model.
