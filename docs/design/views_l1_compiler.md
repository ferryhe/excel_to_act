# Deterministic L1 views

`excel-to-act views compile --handoff HANDOFF --step1-root ROOT --out views.json [--budget N]` reuses Step 2 `build_index` and `validate_saved_index` before reading indexed artifacts. A blocked index or failed validation stops compilation. Batch entries remain separate by Step 2 `source_id`; a missing or ambiguous source identity is an error.

The compiler reads the validated inventory and manifest. It uses the referenced `dependency_graph.json` when Step 1 supplied one; otherwise it calls the existing `RegexFormulaGraphBuilder` on the validated inventory, the same builder behind `graph.build`. The resulting graph is not presented as an independently stored artifact. Checksums, schema and source/run identity of handoff references remain Step 2's responsibility. The compiler also checks inventory and manifest workbook SHA-256 against the Step 2 source entry.

Each source yields one `workbook` view, one `sheet` view per inventory sheet, and a `region` view for each `SheetInventory.ranges` entry with a valid rectangular A1 address. A region includes its source range record, cells within its row/column bounds, and fully contained `SheetInventory.ranges`. Its `region_address` and `SourceLocation` retain the original address; its `view_id` includes the stable source range record ID. Layout objects, opaque fields, invalid addresses, and multi-area strings do not create regions. The compiler does not invent ranges or expand outside the inventory's recorded cells/ranges.

Workbook records cover workbook ranges, package parts, VBA modules (located at the actual `vbaProject.bin` package part), and unsupported features. Sheet records cover cells, ranges/layout, graph dependencies, and unresolved references. A dependency keeps its actual graph node IDs and explicitly records `cross_sheet`; unresolved references remain diagnostics, never invented edges. Region records repeat their source records by design; the sheet view remains the complete sheet projection.

`view_id` is a SHA-256 prefix over Step 2 source ID, scope, sheet name (or empty string), and view key (or empty string). Workbook and sheet views use an empty view key. A region uses the stable `record_id` of its source range, so distinct ranges on one sheet have distinct IDs. `record_id` is a SHA-256 prefix over source ID, record kind, exact `SourceLocation`, and record facts. Record order follows source inventory/graph order. Cell and range locations preserve sheet and address. Package and VBA locations preserve source `object_id` and `ooxml_part`; no workbook A1 address is synthesized.

`--budget` is an estimated-token budget per chunk, using `ceil(serialized_record_utf8_bytes / 4)`. It is deterministic, not a tokenizer count. Records are never split or omitted. A single record over budget occupies its own chunk and appears in `over_budget_record_ids` and the view's opaque report when applicable. Output is sorted-key UTF-8 JSON without timestamps.

The runtime schema is `WorkbookView` (exported from `excel_to_act.schemas`); use `artifact_json_schema(WorkbookView)` to export its JSON Schema. Agent responses can be checked with `excel-to-act views validate --views views.json --output response.json` or `validate_agent_output`.
