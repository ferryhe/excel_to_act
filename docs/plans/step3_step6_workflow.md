# Reusable six-step conversion workflow

Use the same workflow for each source, with Excel workbooks under `input/` and a new source-bound workflow directory under `output/`. Keep each workflow's targets, input catalog, scenarios, design and evidence together. Business names, worksheet coordinates, projection lengths, input counts, excluded calculations and expected values come from that source and the user's decisions. Case studies are examples, not defaults.

Each stage pairs its `agent.md` instructions with a real `tools/` CLI catalog. The packaged `stepN agent` command publishes the stage instructions; `stepN tools` publishes its current capabilities. The Agent selects tools for the current source, explores from source-bound evidence, checks outputs, and prepares the paired JSON and Markdown handoff. A generic Agent contract does not make the implemented formula subset, external-capture path or reconciliation adapter support every workbook. Check those limits for each accepted design and report missing support before execution. Store source-specific facts and decisions in the current workflow's bound reports, not in reusable documentation. The [Agent contract](../design/generic_agent_contracts.md) explains this boundary.

## Stages and deliverables

| Stage | Work and CLI | Deliverables | Required review |
| --- | --- | --- | --- |
| 1 — Extract and preserve | `step1 convert`, `check`, `finalize`, `report` | Source copy, preserved package parts, inventories, handoffs, `import_checkpoint.json/.md` | Agent + actual human |
| 2 — Index | `step2 index`, `validate`, `report` | Navigation index, validated source/artifact references, `index_checkpoint.json/.md` | Agent + actual human |
| 3a — Confirm inputs | Static `step3` exploration, then `input-catalog` | Targets, scalar/vector/table input catalog, groups, source locations, raw/external boundaries, unresolved inputs, `input_boundary.json/.md` | Agent + actual human; this does not approve final design |
| 3b — Analyze and design | `source-trace`, `profile`, `plan`, `check`, `report` | Target/path/options ledger, variable/axis/recurrence design, semantic mapping/check, `analysis_design.json/.md` | Agent, then actual human by default; valid scoped delegation may apply to this final design |
| 4 — Generate code | `capture-external` when required by the supported modular path, `discover`, `plan`, `generate` | Bound external inputs, active source trace, implementation preflight, compact standalone Python, separate raw/external/metadata ledgers, source map, `generation_report.json/.md` | Agent, then actual human by default; valid scoped delegation may apply |
| 5 — Validate and reconcile | `validate`, `oracle`, `reconcile` | Isolated execution evidence, fresh native Excel capture, formula/value/error comparisons, coverage and tolerance results, `validation_report.json/.md` | Both technical checks pass, then Agent and actual human by default; valid scoped delegation may apply |
| 6 — Final report | `report` | `conversion_report.json/.md`: accepted artifacts, results, coverage, code/run instructions, limits and open items | Agent, then actual human by default; valid scoped delegation may apply |

Step 3 works backward from one value, several values, a column or a finite region. It confirms the input boundary before final design, then explains conditional paths, shared modules, scalar versus time-series variables, initialization, recurrence order, category axes, equation families and implementation options. Unknown closure or coverage stays unknown. Step 3 does not calculate formulas, capture external values, generate runnable code or establish equivalence with Excel.

Step 4 rereads the hash-bound formula-mode source and emits logical-variable code from the accepted design and source-family mappings. Use compact functions, aligned vector/category operations, ordered recurrence loops and reductions. Keep physical coordinates in the source map and adapter. Formula caches, active-trace calculated values and earlier model results must not become raw model constants. Explicitly accepted formula-derived external inputs have their own later-stage capture and provenance. Unsupported active formulas, unresolved dependencies, cycles or missing adapter support block generation.

The standalone bundle runs without the workbook or project package. Review its manifest-listed files and source bindings rather than assuming a fixed file count or source layout. The isolated generation smoke proves execution only. Step 5 repeats isolated validation and independently compares against fresh native Excel results for the same source and declared scenario. The native tool uses a private read-only copy, disables macros/events, performs a full rebuild, and closes without saving. It requires Windows with Microsoft Excel. An oracle capture alone does not approve or advance Step 5.

## Reviews, revisions and return routes

Every stage binds its JSON/Markdown pair, revision, source hash and upstream inputs. The default order is Agent review followed by actual human review of the exact current pair. The workflow rejects a new human or TypeSafe approval until a matching Agent approval exists for that JSON and Markdown revision. Human decisions require an explicit user response. Only a valid explicit delegation may replace the human reviewer for final Step 3 and Steps 4–6; TypeSafe remains a distinct reviewer and also follows Agent review. A fresh actual-human approval under that valid delegation restores Agent+human review for that exact artifact revision; the authorization remains unchanged. The input catalog always retains actual human review.

Run `workflow status --workflow DIR` before entering a stage and before each transition; verify the stage is currently permitted and required upstream decisions and artifacts are current. A successful draft or report command does not itself advance a stage. Legacy standalone source-exploration APIs remain available for discovery and do not create workflow approvals. Use `workflow confirm` or `workflow reject` to record decisions, not a file edit. Ask the user when a target, scope, input kind, axis, units, or business interpretation remains materially unresolved; clarification is not a final stage decision. A rejection returns to the stage responsible for the problem: source to Step 1, index to Step 2, scope/equations to Step 3, implementation to Step 4, missing or failed comparison to Step 5, report defects to Step 6. Preserve rejected and accepted history. Changed source, inputs, reports or upstream revisions invalidate affected decisions and require new artifacts and reviews.

Each primary report starts with what the person is being asked to accept, its purpose and scope, key verified results, limits and unresolved choices, links to the machine and human handoffs, and the next review action. Detailed source evidence, question history and hashes stay available in the same report's appendix and JSON. A `pass` or `ready_for_review` value describes technical report integrity; `workflow.json` is the current acceptance ledger.

For delegated reviews, register `workflow delegate --workflow DIR --authorization AUTH.json`, submit a current-bound live request with `workflow typesafe --workflow DIR --stage N --request REQUEST.json`, and import only its generated evidence with `workflow confirm ... --reviewer typesafe --evidence REVIEW.json`. Handwritten responses, below-threshold decisions and insufficient confidence cannot release a gate. Do not lower thresholds to conceal an unresolved review.

Step 6 can be produced only after Steps 1–5 are current and approved. It reports measured scope; a tested scenario does not imply all configurations, complete actuarial correctness, feedback solving or GPU support. Successful technical tests and formal stage acceptance are separate states.
